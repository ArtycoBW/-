# ФСП и проверка на независимой разметке — 11 октября 2026

## Что теперь реализовано

Связь профиля с внешней учётной записью через OpenID Connect: authorization code, PKCE S256, одноразовый state на пять минут, nonce, проверка RS256/JWKS, issuer, audience и срока действия. Идентификатор строится из issuer + subject, а не из совпадения email. Одна внешняя учётная запись не может принадлежать двум профилям. Можно отвязать учётную запись; отсутствие истории достижений не мешает работе кандидата.

Для воспроизведения используется **локальный Keycloak и учебный реестр**. Это самостоятельный тестовый контракт, а не опубликованный контракт Федерации. Официальные данные, права доступа и совместимость с будущим API ФСП не подтверждены. Согласно исходному ТЗ, API и описание структуры данных намеренно не предоставлены для хакатона.

Эндпоинты приложения: `GET /api/v1/integrations/fsp/oidc/status`, `POST .../start`, `GET .../callback`. Реестр-симулятор возвращает `{"achievements": [...]}` с полями `external_id`, `title`, `discipline`, `date`, `place`, `participants`; допустим пустой список. Источник учебных достижений сохраняется как `local_oidc`. Не показывать их как подтверждённые Федерацией.

## Запуск отдельного локального стенда

В корне проекта создать **не отслеживаемый Git** файл `.local/fsp-local.env` с `FSP_FLOW_SECRET=<случайная строка не короче 32 символов>`. Пример генерации: `python -c "import secrets; print('FSP_FLOW_SECRET='+secrets.token_urlsafe(48))"`. Не публиковать значение.

```powershell
docker compose --env-file .local/fsp-local.env -f compose.review.yml -f compose.fsp-local.yml up -d --build
```

Приложение: http://localhost:3102. Keycloak: http://localhost:8089. Оба порта привязаны только к loopback. В настройках профиля нажать «Войти в локальный ФСП ID».

| Учебный пользователь Keycloak | Пароль | История |
| --- | --- | --- |
| `fsp-history` | `LocalFsp2026!` | Один учебный турнир |
| `fsp-empty` | `LocalFsp2026!` | Пустая |

Если Keycloak предлагает повторный вход в предыдущую учётную запись, нажмите «Restart login», чтобы выбрать другого учебного пользователя.

Эти публичные учебные пароли предназначены только для отдельного локального стенда. Не включать данный overlay на публичном сайте. Регистрация в самом приложении работает без кода почты. Действующий публичный сайт и его туннели не зависят от этого compose-проекта.

Для официального сервиса потребуются его документированный контракт, issuer, client ID, права/scopes, при необходимости client secret, разрешённый callback URL и адрес реестра. После получения необходимо адаптировать контракт достижений, проверить реальные токены и правила доступа. Простая замена адреса учебного реестра не является подтверждением совместимости.

## Независимые оценки: реально полученный набор

Использован открытый [репозиторий авторов Vanetik и Kogan](https://github.com/NataliaVanetik/vacancy-resume-matching-dataset), сопровождающий работу *Job Vacancy Ranking with Sentence Embeddings, Keywords, and Named Entities*, Information 14(8), 468, 2023, DOI 10.3390/info14080468.

Зафиксирован commit `7ee8f043c6e31ee94cb67f5e60b069901b533adf`. В репозитории присутствует лицензия GPL-3.0. Исходные резюме и обученный локальный артефакт не включены в наш репозиторий и не отправлялись внешним моделям. Публикуются код проверки, атрибуция, хеши источников и агрегированные метрики. Перед распространением самого корпуса/производных артефактов необходимо соблюдать лицензию источника.

Доступны 65 анонимизированных резюме, ранжирования **первых 30 резюме относительно пяти ИТ-вакансий двумя разметчиками**, инструкция разметки с участием HR. Это человеческие предпочтения, а не результаты найма. В строках резюме №9 и №28 первый разметчик повторил позиции вакансий; обе записи исключены целиком. Осталось 28 резюме: 18 для обучения, 10 для отложенной проверки. Разделение по людям зафиксировано seed `20261011`; пять вакансий известны в обеих частях.

Обучена **отдельная экспериментальная текстовая модель**: word/character TF-IDF, пересечение извлечённых навыков, pairwise logistic regression. IDF обучен только на тренировочных резюме и пяти известных вакансиях. Тестовые резюме не использовались при обучении словаря, коэффициентов или настройке параметров. Сохранены локальные векторизаторы и модель; повторная загрузка воспроизводит оценки. Основная продуктовая модель не заменена.

| Метод | NDCG@3 на 10 отложенных резюме |
| --- | ---: |
| Текущая составляющая совпадения навыков | 0,6511 |
| Ожидаемое случайное ранжирование | 0,7053 |
| Среднее word/character TF-IDF | 0,7634 |
| Экспериментальная модель на человеческих оценках | 0,8031 |

95% bootstrap-интервал разницы модели и TF-IDF: **от −0,0150 до +0,0944**. Интервал включает ноль: уверенное преимущество не установлено. Среднее согласие разметчиков Kendall τ = **0,1357**, поэтому разметка неоднозначна. Составляющая совпадения навыков на этом пилоте уступила случайному ранжированию; это полезный отрицательный результат, а не основание объявлять качество подтверждённым.

В наборе нет результатов наших тестов, разрядов, активности и достижений ФСП. Проверено ранжирование вакансий для резюме; продукт также решает обратную задачу подбора кандидатов работодателю. **Полная модель из шести признаков всё ещё не прошла независимую внешнюю валидацию.** Нужна более крупная релевантная выборка с российскими ИТ-профилями и оценками специалистов. Инструмент `ml.human_review` позволяет собрать слепую разметку таких пар, не выдавая синтетические оценки за экспертные.

## Воспроизведение

```powershell
git clone https://github.com/NataliaVanetik/vacancy-resume-matching-dataset .local/external/vanetik2023
git -C .local/external/vanetik2023 checkout 7ee8f043c6e31ee94cb67f5e60b069901b533adf
.venv/Scripts/python.exe -m ml.external_benchmark --data .local/external/vanetik2023
```

Отчёт: `.local/external-benchmark/report.json`; локальный артефакт: `text-model.joblib`. Загружать joblib можно только из доверенного локального процесса, поскольку это формат pickle. Проверенная копия отчёта без текстов резюме: `ml/external_metrics.json`.

ConFit, CareerBERT и Emory ECLAIR не использовались для обучения: получение полного корпуса и/или пригодность разметки оставались неподтверждёнными. Запросы авторам не отправлялись.

## Проверка реализации

Backend и ML: `python -m pytest tests -q` — 75 проверок. Проверены одноразовость и принадлежность state, неверная подпись/issuer/audience/nonce, истёкшие токены, конфликт идентификатора, отмена входа и пустая история. На копии PostgreSQL миграция сохранила 485 существовавших пользователей.

Для браузерного прогона из каталога `frontend`:

```powershell
$env:PLAYWRIGHT_BASE_URL='http://localhost:3102'
$env:FSP_LOCAL_E2E='true'
$env:E2E_DATABASE='postgres'
$env:E2E_COMPOSE_FILE='compose.review.yml'
npx playwright test
```

Переменная `E2E_COMPOSE_FILE` направляет доверенную тестовую фикстуру ответов в проверочную базу. Это не публичный API и не способ выдачи ответов пользователю. Рабочая база и туннели не используются для тестов.

Браузерная проверка: 16 сценариев прошли — 15 в общем прогоне и один повторно после настройки тестовой фикстуры на PostgreSQL. Сценарий ФСП проверяет настоящий локальный Keycloak, импорт истории, отвязку, смену учебной учётной записи и пустую историю; мобильная страница не имеет горизонтального переполнения.
