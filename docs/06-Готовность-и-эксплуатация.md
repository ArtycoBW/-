# Готовность, модель и эксплуатация

## Что можно утверждать

«Разряд» решает основной демонстрационный сценарий кейса: профиль специалиста, тест выбранного уровня, подтверждённая категория, подбор по потребности компании, приглашение с зарплатой и адресная передача контактов. Дополнительно работают вакансии, отклики, практика с оценкой работодателя, PDF и отзыв доступа к контактам.

Хакатонный стенд версии 1.3 доступен по постоянному HTTPS-адресу. Проверки функциональности, данные обучения и условия промышленного пилота приведены раздельно: результаты синтетических тестов не являются оценкой реального найма.

| Область | Реализовано | Условия промышленного пилота |
|---|---|---|
| Бэкенд | FastAPI, роли, транзакции, сессии, аудит, Alembic, настройки и удаление аккаунта | Интеграционные SLA и проверка на ожидаемой нагрузке |
| Фронтенд | Next.js, русский интерфейс, два кабинета, адаптивность, обработка ошибок, клавиатура, reduced motion | Полный WCAG-аудит, реальные пользовательские исследования и проверка Safari/Firefox |
| Подбор | Фильтрация категории, нормализация стека, формула, экспортированная обученная модель, объяснение и fallback | Независимая экспертная разметка и измерение результатов найма |
| Тестирование навыков | Десять специализаций, три грейда, параметризованный банк, сохранение и таймаут, интервалы повторов | Экспертная калибровка сложности, расширение банка, эмпирическая психометрика и антифрод |
| История ФСП | Маркированный демореестр, профиль без истории, проверенный локальный OIDC/Keycloak | Контракт и права доступа к официальному реестру |
| Хранилище | PostgreSQL, закрытый порт, volume, ежедневный backup с восстановлением в отдельной БД, удаление аккаунта | Внешнее хранение копий и репликация по согласованным RPO/RTO |
| Инфраструктура | Постоянный домен, Cloudflare Tunnel, HTTPS, healthchecks, рестарт контейнеров, локальный мониторинг | Независимый от пользовательского ПК хостинг и внешние оповещения |
| Масштабирование | Пакетная загрузка связей, отсутствие N+1 в подборе | Ранжирование сейчас до пагинации; для большого банка нужен отдельный retrieval-этап, индекс навыков и нагрузочный профиль |
| Уведомления | Реальные письма подтверждения и восстановления; приглашения и отклики в кабинетах | Очередь и дополнительные каналы уведомлений о событиях найма |
| Модерация | Контроль роли и владельца, безопасная выдача контактов | Проверка компаний, кабинет оператора, разбор споров и злоупотреблений |

Развёртывание использует отдельные API для старого и постоянного адресов с общей PostgreSQL. В доменном API 1.3 лимит запросов хранится в БД и действует для реплик с той же базой. Пул соединений и этап предварительного отбора настраиваются по измеренной нагрузке.

## Итоговая модель

Артефакт `ml/model.json` содержит действительно обученные коэффициенты логистической регрессии, порядок признаков, seed и происхождение данных. Бэкенд загружает именно этот файл. Формула даёт 70%, модель 30% итогового балла. Если файл отсутствует или повреждён, подбор продолжает работать по формуле. Контакты, имя и защищённые характеристики не являются признаками модели.

Модель обучена на 5 120 синтетических парах; валидация использует 1 280 пар, тест 1 920. Группы потребностей и кандидатов разделены. Метрики, SHA-256 и настройки зафиксированы в `ml/metrics.json`. JSON экспортирован без исполняемого pickle. Тест проверяет совпадение SHA-256 и монотонность оценки при улучшении навыков.

Дополнительная проверка `ml/evaluate_robustness.py`: пять новых seed, 400 подборок и 12 800 пар, случайное ранжирование как контроль, отключение истории ФСП, парный bootstrap на уровне подборок. Средняя разница NDCG@5 «гибрид минус формула» составляет 0,01159; 95% bootstrap-интервал [0,00932; 0,01400]. Результат сохранён в `ml/robustness.json`.

Почему этого недостаточно для «финальной модели реального найма»: все выборки происходят из одной программно заданной модели предпочтений, близкой по признакам к самой формуле. Высокий NDCG ожидаем; он не означает 99% точности найма. Новые seed проверяют устойчивость, а не внешнюю валидность. Случайные метки не являются отзывами работодателей. Не установлены реальные fairness, калибровка вероятностей или прирост трудоустройства.

Практический следующий шаг: независимые оценки экспертов по парам «потребность + профиль», временное разбиение без пересечений участников, сравнение с формулой и случайным контролем, A/B-пилот с явным согласием и мониторингом обратной связи. До этого модель помогает сравнивать профили, но не принимает автоматические решения об отказе.

## Публичный демонстрационный стенд

```powershell
docker compose up --build -d
docker compose exec api python -m backend.demo_scenarios
powershell -ExecutionPolicy Bypass -File scripts/start-tunnel.ps1
```

Скрипт получает временный HTTPS-адрес, записывает его в `.local/public-url.txt`, выставляет точный `PUBLIC_ORIGIN`, защищённую cookie и доверие заголовку IP от Cloudflare. База и API напрямую наружу не публикуются. Туннель открывает только web-сервис; Mailpit остаётся на localhost. Переменные и логи не включаются в Git.

Проверка текущего внешнего HTTPS-стенда: `/api/v1/ready` отвечает успешно; вход в подготовленные аккаунты двух ролей и регистрация без письма работают. Cookie сессии имеет Secure и HttpOnly. Запрос изменения состояния с посторонним Origin отклонён кодом 403. Ошибок JavaScript в этом браузерном сценарии не было. Проверки выполнены на Chromium; это не полное межбраузерное или нагрузочное испытание.

Актуальный протокол автоматических и визуальных проверок версии 1.2 находится в документе 09. Ранние измерения на меньшем наборе данных не используются как показатели текущего стенда.

Quick Tunnel сохраняет адрес прототипа из заявки. Постоянный сайт https://razryad.agropulseai.ru использует отдельный именованный туннель. Для обоих входов нужны работающие ПК, Docker и сеть. Старый туннель при обновлении доменного API не перезапускается.

На публичной демонстрации `DEMO_MODE=true` намеренно даёт доступ к общим учебным аккаунтам. Для реального пилота отключите демонстрационные методы и загрузку фикстур. Регистрация без проверки почты не доказывает владение адресом и не заменяется Cloudflare Tunnel; это отдельная продуктовая настройка по текущему решению команды.

`EMAIL_VERIFICATION_REQUIRED=false`, `PASSWORD_RECOVERY_ENABLED=false`, `EXPOSE_DEMO_MAIL=false`: ни подтверждение, ни восстановление через недоставляемое письмо не предлагаются. При подключении настоящего SMTP функции можно включить. Нельзя открывать публично `EXPOSE_DEMO_MAIL=true`: этот параметр предназначен исключительно для изолированных тестов.

## Резервные копии и восстановление

```powershell
.venv/Scripts/python.exe scripts/backup.py
```

Согласованный `pg_dump -Fc` сохраняется в `.local/backups`. Скрипт проверяет каталог архива через `pg_restore --list`. Проверка полного восстановления выполняется `scripts/verify-backup.py`: создаётся отдельная временная БД, туда восстанавливается архив, проверяются ключевые таблицы, после проверки удаляется только эта временная БД. Рабочая БД не заменяется.

Для восстановления рабочей БД сначала остановите записи, сделайте дополнительный backup и проверьте архив в отдельной БД. Замена работающей БД требует отдельного решения оператора. `docker compose down` сохраняет volume; `down -v` удаляет данные и не является обычным перезапуском.

## Зависимости и границы проверок

Runtime-проверка `npm audit --omit=dev` не выявила известных уязвимостей на момент сборки. Полный audit показывает пять high-записей в цепочке инструментов ESLint из-за `braces@3.0.3`; совместимое исправление на момент проверки отсутствует. Автоматически откатывать Next.js на старшую уязвимую/несовместимую ветку ради зелёного отчёта нельзя. Эта dev-цепочка не входит в standalone runtime.

Успешные тесты подтверждают конкретные сценарии и ограничения. Они не означают отсутствие всех ошибок, аудит всей безопасности, соответствие любому объёму нагрузки или готовность работать с реальными персональными данными без дополнительных организационных мер.
