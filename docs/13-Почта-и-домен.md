# Почта и постоянный домен

## Рабочая конфигурация

На 11 октября 2026 года выпуск 1.3 работает по адресу https://razryad.agropulseai.ru. Публичные HTML, /api/v1/health и /api/v1/ready возвращают HTTP 200, база доступна. Прототип из заявки https://especially-eng-finally-walt.trycloudflare.com сохранён. Старые сервисы и оба туннеля при включении почты не перезапускались.

| Компонент | Действующая настройка |
|---|---|
| NS | brodie.ns.cloudflare.com, rosalie.ns.cloudflare.com |
| Маршрут сайта | Именованный Cloudflare Tunnel → domain-web:3000 → domain-api |
| MX | mx1.timeweb.ru, приоритет 10; mx2.timeweb.ru, приоритет 20 |
| SPF | v=spf1 include:_spf.timeweb.ru ~all |
| DKIM | TXT dkim._domainkey.agropulseai.ru; опубликован ключ Timeweb |
| Отправитель | Разряд <noreply@agropulseai.ru> |
| SMTP | smtp.timeweb.ru:587, STARTTLS с проверкой сертификата и имени сервера |
| Сессия | Cookie Secure, HttpOnly, SameSite=Lax |

NS, адрес сайта, MX, SPF и DKIM проверены через Google DNS и Cloudflare DNS. Учётные данные SMTP находятся только в приватном .local/domain-api.env. Не публиковать вывод окружения контейнеров, пароли, cookies или токены.

```dotenv
PUBLIC_ORIGIN=https://razryad.agropulseai.ru
COOKIE_SECURE=true
EMAIL_VERIFICATION_REQUIRED=true
PASSWORD_RECOVERY_ENABLED=true
EXPOSE_DEMO_MAIL=false
```

Настройки провайдера: https://timeweb.cloud/docs/mail/email-clients-configuration

## Что видит пользователь

1. Новый пользователь регистрируется с доступным ему почтовым адресом. До подтверждения вход закрыт.
2. Письмо от noreply@agropulseai.ru содержит одноразовую ссылку со сроком один час. Подтверждение выполняется по ссылке, числовой код не используется.
3. Кнопка «Нет письма?» повторно отправляет подтверждение. Новый токен заменяет прежний токен того же назначения.
4. «Забыли пароль?» отправляет отдельную ссылку сброса. После смены пароля старый пароль и прежние сессии недействительны.
5. Все 15 общих аккаунтов комиссии подготовлены для входа без писем на вымышленные адреса. Это учебные профили; их доступность не означает подтверждение владения реальными ящиками. Обычные аккаунты проходят почтовую проверку.

На старом прототипе из заявки сохранён прежний режим регистрации. Для проверки обязательного подтверждения и восстановления используется постоянный домен.

## Повторная проверка и обслуживание

`python scripts/domain-release.py` проверяет публичный DNS, почтовые записи, HTTPS, API, БД и прежний адрес. Код выхода 0 означает готовность, 2 — незавершённую проверку. Результат сохраняется в .local/domain-release/preflight.json. Скрипт не меняет Docker или DNS.

Перед изменением доменной конфигурации сохраняются её приватная копия и резервная копия БД. Применение настроек затрагивает только доменный API:

```powershell
docker compose --env-file .local/domain.env -f compose.domain.yml up -d --no-deps domain-api
```

Не выполнять compose down и не перезапускать туннели для изменения почтовых флагов. При подтверждённой недоставке писем оператор возвращает прежнюю безопасную конфигурацию и проверяет доступность регистрации.

`python scripts/domain-release.py --verify-mail` повторяет описанный тест только при готовом DNS и включённых флагах. Он использует собственный тестовый аккаунт и удаляет его через API. Если существует .local/domain-release/test-account.json, повторная регистрация блокируется: сначала нужно проверить сохранённое доказательство владения и состояние теста. Нельзя удалять этот маркер вслепую или изменять существующего пользователя с совпавшим email.

`--notify` защищён журналом notification.json от повторной отправки. Итоговое уведомление уже отправлено; повторять его не нужно. Состояние pending означает неопределённый результат SMTP и требует проверки факта отправки.

Для старого набора учебных аккаунтов предусмотрена `python -m backend.demo_access`: только DEMO_MODE, ровно 15 опубликованных адресов, проверка роли, публичного учебного пароля и идентификаторов judge-профилей. Меняется только допуск к входу; при несовпадении любой проверки транзакция отменяется. Перед применением нужна резервная копия БД. Новые наборы создаются с корректным признаком допуска.

Локальные результаты и приватные журналы хранятся в .local/domain-release и не включаются в Git. Сайт размещён на ПК: нужны работающие ПК, Docker и интернет.
