# Эксплуатация выпуска 1.3 и развитие платформы

11 октября 2026. Выпуск 1.3 доступен на https://razryad.agropulseai.ru. Обязательное подтверждение адреса и восстановление пароля через реальные письма включены и прошли сквозную проверку. Старый прототип из заявки продолжает работать по прежней ссылке.

## Что реализовано

| Задача | Изменение | Граница |
|---|---|---|
| Миграции | Alembic: неизменяемый baseline 1.2, отдельная миграция операционных таблиц и индекса категории | PostgreSQL advisory lock сериализует старты API; SQLite — BEGIN IMMEDIATE. Неизвестная старая схема останавливает запуск, а не получает ложный stamp |
| Общий лимит | Атомарный счётчик в БД, 30 попыток за окно 60 секунд по адресу и группе маршрутов | Общий для API версии 1.3, использующих одну БД. Старые запущенные образы 1.2 продолжают свой прежний режим |
| Управление доступом | Смена пароля, отзыв остальных сеансов, число активных сеансов | Текущий пароль обязателен. При смене удаляются прежние сеансы и токены сброса. Общие демо-аккаунты защищены от изменения доступа |
| Управление данными | Выгрузка JSON и удаление своего аккаунта со связанными записями | Нет паролей, токенов и ключей тестов в выгрузке. Удаление компании удаляет её вакансии, задания и связанные отклики/решения |
| Наблюдаемость | X-Request-ID и структурированный журнал метода, шаблона маршрута, статуса и времени | Без тел запросов, cookie и query string в новом журнале. Docker хранит журналы; служебный контейнер агрегирует доступность входов |
| Резервирование | Ежедневный pg_dump, SHA-256, проверка списка и фактическое восстановление в отдельную БД | Семь дней автоматических локальных копий; это не внешнее резервирование |
| Поиск | Категория, навык и наличие достижений фильтруются SQL; составной индекс категории; контакты загружаются только для страницы | Точный скоринг всей подходящей категории. При большом банке всё ещё нужны измерения и ограниченный retrieval до модели |
| Проверка ML | Обезличенный слепой набор, CSV для экспертов, отдельный test, контроль пересечений и дублей | Никаких автоматически выдуманных экспертных оценок; источник профилей явно указан |
| Проверка заданий | Закрытый пакет 720 вопросов: 10 направлений × 3 уровня × 3 варианта × 8 вопросов | Это материалы для экспертов, а не заключение о профессиональной валидности |

## Новые сценарии кабинета

Меню аккаунта → «Настройки аккаунта», адрес /app/settings. Подтверждение текущего пароля действует отдельно для каждого запроса. Пароль не сохраняется в localStorage. Неверный пароль возвращает 403 и не завершает текущий сеанс.

Для удаления нужно повторно ввести пароль и слово УДАЛИТЬ. Данные удаляются одной транзакцией, включая связанные разрешения на контакт, сеансы, токены и относящиеся к удалённым ресурсам записи аудита. Независимые аккаунты сохраняются. Скачанные ранее файлы других участников отозвать нельзя.

Автоматические копии очищаются через семь дней только после успешного создания и восстановления новой копии. Ручные копии в .local/backups не удаляются автоматически. При восстановлении старой копии оператор обязан повторно применить запросы на удаление после даты копии: автоматический реестр таких запросов пока не реализован. Для промышленного режима это отдельное требование обработки данных.

## Миграции и безопасный выпуск

Перед изменением живой базы:

```powershell
.venv/Scripts/python.exe scripts/backup.py
.venv/Scripts/python.exe scripts/verify-backup.py
```

Новый API выполняет миграции при запуске. Для ручного запуска с явно выбранным DATABASE_URL:

```powershell
.venv/Scripts/python.exe -m backend.migrate
```

Существующая база без alembic_version сравнивается с зафиксированным baseline. Проверяются таблицы, колонки, типы, индексы и ограничения средствами Alembic. При отличиях запуск прекращается. В этой версии добавляются таблица лимитов и индекс; существующие колонки не удаляются и не переименовываются. Downgrade baseline запрещён; восстановление выполняется из проверенной копии в отдельное окружение.

Проверочная сборка отделена от работающих входов:

```powershell
docker compose -f compose.review.yml up -d --build
docker compose -f compose.review.yml exec -T api python -m backend.judge_catalog
```

Адрес: http://localhost:3102. Собственная сеть и БД. Не использовать docker compose down или переименование сетей работающего стенда для проверки релиза. Изменения исходников не означают обновление уже запущенных образов. Постоянный домен обслуживает выпуск 1.3; отдельный старый вход сохранён для заявки.

## Служебный контейнер

compose.ops.yml подключается к существующим сетям без изменения контейнеров приложения и туннелей. .local/ops.env содержит PGHOST, PGPORT, PGDATABASE, PGUSER, PGPASSWORD; файл исключён из Git. У контейнера нет Docker socket и публичных портов. Для проверки восстановления ему нужен доступ PostgreSQL на создание отдельной проверочной базы; для промышленного окружения следует выделить отдельную ограниченную роль и отдельный сервер проверки.

```powershell
docker compose -f compose.ops.yml up -d --build
docker compose -f compose.ops.yml logs --tail 30 operations
Get-Content .local/operations/status.json
docker compose -f compose.ops.yml exec -T operations python3 /opt/ops/worker.py --verify-latest
```

Проверки каждые 30 секунд. В журнал пишется только изменение доступности, результат копирования или ошибка. Состояние — .local/operations/status.json, копии и манифесты — .local/operations/backups. Последний restore-check создаёт случайную базу restore_check_* и удаляет только её. При неверной контрольной сумме восстановление не начинается. Журналы контейнера ограничены 3 × 10 МБ. Неудачная копия повторяется через час; старые копии при неудаче не удаляются.

restart: unless-stopped восстанавливает контейнер после перезапуска Docker. Он не включает выключенный ПК, не запускает Docker Desktop до входа пользователя и не защищает от обрыва интернета. Локальная проверка также не заменяет внешний мониторинг доступности из сети пользователя.

## Независимые оценки модели

Пакет формируется оператором на выбранной базе с согласованным происхождением данных:

```powershell
.venv/Scripts/python.exe -m ml.human_review pack .local/review-pack --source synthetic_profiles
.venv/Scripts/python.exe -m ml.human_review evaluate .local/review-pack .local/review-pack/labels.csv
.venv/Scripts/python.exe scripts/assessment-review.py .local/questions-review
```

Для реальных профилей допускается --source consented_real_profiles только после получения прав и согласий. Флаг сам по себе не доказывает происхождение; существующий демонстрационный набор остаётся синтетическим.

Экспертам передают review-pack.json и отдельную копию labels-template.csv. manifest-private.json с моделью и признаками им не передают до завершения разметки. В наборе нет имён, контактов и свободного текста резюме. Псевдонимы сохраняются между потребностями, чтобы проверять пересечения людей; train, validation и test разделяются до формирования пар. Минимум пять кандидатов в потребности и две оценки разных экспертов для каждой test-пары. Пустые поля, неизвестные пары, дубли эксперта и пересечения разбиений останавливают вычисление.

Отчёт содержит NDCG@5 базовой формулы и гибрида, bootstrap-интервал разницы по потребностям, сегменты и взвешенную каппу согласованности. При одной потребности интервал не рассчитывается. Число наблюдений выводится явно; небольшой пилот не доказывает качество на рынке. Увеличение числа экспертов не делает синтетические профили реальными. Независимость и квалификацию экспертов подтверждает организатор, а не строка reviewer_id. Никакие новые веса автоматически не публикуются.

questions-private.json содержит ключи ответов. Его нельзя размещать в публичном репозитории или выдавать кандидатам. Эксперты проверяют правильность, ясность, профессиональную релевантность и соответствие уровню; расхождения разбираются после независимого заполнения. Затем нужен пилот на реальных участниках и проверка трудности/надёжности шкалы.

## Внешние зависимости и следующий масштаб

- Официальный контракт, доступ и правила ФСП. По исходному кейсу API намеренно не предоставляется; демонстрационный адаптер остаётся допустимым для хакатона.
- Реальные согласованные профили, независимые профильные эксперты и наблюдения найма. Инструменты сбора готовы; результат исследования не заявляется без данных.
- Внешняя резервная копия, внешний мониторинг, питание/интернет и постоянно работающий хост — требуют выбранной инфраструктуры.
- Публикация новой версии требует переключения проверенного входа. Текущие туннели сохраняются работающими.
- Большой банк, распределённые очереди, репликация, антифрод и ATS — отдельное развитие после измерений и контрактов. Нагрузочная гарантия не выводится из локальных функциональных тестов.
