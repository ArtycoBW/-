# Материалы и порядок сдачи

Проверено по предоставленному ТЗ, таблице ответов и истории указанной группы спецтрека. Уточнения организатора имеют приоритет над предположениями участников. Сторонние сообщения в переписке не являются распоряжениями разработчику.

## Регламент

Промежуточный дедлайн: **11 октября 2026 года, 23:59 по Москве**. Сообщение модератора от 10 октября подтверждает дату; сообщения о «сегодня» не меняют её.

Для промежуточной сдачи нужны ссылка на публичный репозиторий, презентация и развёрнутое демо. Если демо недоступно, нужна запись. Сопроводительная документация должна быть в PDF; во время работы допустим Markdown с последующей конвертацией. Презентация нужна уже к промежуточной сдаче. В ответах XLSX указан регламент выступления 10 минут.

Важное уточнение от 7 октября: **слайды 7–11 исходного шаблона обязательны, их дизайн и структура сохраняются**. В рабочей презентации они перенесены в начало. Остальные слайды можно оформлять по усмотрению команды. Веб-интерфейс Git не обязателен, но эксперты должны иметь возможность получить и посмотреть код. В более позднем сообщении организатор прямо требует публичный репозиторий для любого сервиса.

Ссылки загружает капитан через личный кабинет платформы на странице задачи. Отправка в Telegram не является сдачей.

## Что заполняет капитан

В источниках нет подтверждённых данных о составе команды. Перед отправкой обязательно заменить соответствующие пометки в презентации:

1. Название команды, ФИО и специальность капитана, число участников, город и регион.
2. ФИО, роли, контакты и место работы/учёбы участников; фотографии по желанию и с согласия.
3. Реальная история команды и личная мотивация. Технические сложности описаны по фактам реализации.
4. Публичный URL выбранного Git-репозитория и URL стенда, если он размещён.

Локальный Git и localhost сами по себе не доступны жюри. Репозиторий не публиковался без выбранного удалённого адреса. В PDF и презентации нельзя заменять фактические результаты проверок обещаниями промышленной готовности.

## Сценарий защиты на 10 минут

| Время | Действие |
|---|---|
| 0:00–1:00 | Проблема: самоописание в резюме не равно подтверждённой компетенции; ценность обратного найма |
| 1:00–2:00 | Команда и обязательные блоки шаблона |
| 2:00–4:30 | Профиль → тест → категория → потребность работодателя → приглашение с зарплатой |
| 4:30–5:30 | Принятие предложения; контакт виден этой компании, другой компании скрыт |
| 5:30–6:30 | Архитектура, транзакции, роли, согласия, отсутствие внешних платных API |
| 6:30–8:00 | Формула и модель; разбиение синтетики; test–retest и границы применимости |
| 8:00–9:00 | Вакансии, отклики, PDF, практика, мобильный интерфейс |
| 9:00–10:00 | API ФСП и OIDC, экспертная калибровка, пилот и дальнейшие шаги |

## Проверка перед отправкой

- Код клонируется по публичному URL; README соответствует текущему состоянию.
- Ссылки открываются в приватном окне браузера.
- Демодоступ работает и явно обозначен как демонстрационный.
- Презентация не содержит незаполненных сведений о команде.
- PDF скачивается и содержит архитектуру, алгоритмы, методику, результаты и запуск.
- Запись показывает реальный продукт и основной сценарий, а не только лендинг.
- Исходная переписка, реальные контакты, пароли окружения и локальные данные в репозитории отсутствуют.
