# Разряд: реализация и эксплуатация

Версия 1.0, 10 октября 2026 года. Этот документ описывает работающий прототип, а не обещания из дорожной карты. Исходные требования и критерии приёмки находятся в техническом задании.

## 1. Архитектура

Браузер обращается к Next.js по одному адресу. Запросы `/api/v1/*` проксируются в FastAPI. Cookie сессии остаётся HttpOnly, токен не хранится в localStorage. FastAPI проверяет роль и владельца объекта, выполняет доменную операцию в транзакции и обращается к SQLAlchemy. В контейнерах используется PostgreSQL 17, в локальном сценарии — SQLite с WAL и внешними ключами.

Поток данных: браузер → Next.js → FastAPI → SQLAlchemy → БД. Ответ подбора проходит отдельный сериализатор контактов. Модуль ранжирования получает только структурные признаки. SMTP поддерживает опциональные одноразовые ссылки; в текущей демонстрации подтверждение и восстановление по почте отключены. PDF разбирается на сервере и возвращает черновик для ручного подтверждения. Произвольный код кандидата не исполняется.

| Компонент | Назначение | Основные файлы |
|---|---|---|
| Frontend | Лендинг, две роли, формы и состояния | frontend/src/views/product, frontend/src/views/home |
| API | HTTP, авторизация, доменные переходы | backend/main.py, security.py, schemas.py |
| Хранилище | Сущности, связи, транзакции | backend/models.py, db.py |
| Тестирование | Параметризованные варианты и проверка | backend/assessment.py |
| Подбор | Признаки, формула, безопасная загрузка модели | backend/matching.py |
| Обучение | Синтетика, независимые разбиения и метрики | ml/train.py, model.json, metrics.json |
| Демоданные | Идемпотентное наполнение стенда | backend/seed.py |

Frontend: Next.js 16.4, React 19, TypeScript, Tailwind 4. Предоставленный Relay сохранён как основа лендинга: композиция, spring-анимации, Lenis, декоративная Three.js-сцена. Кабинеты имеют отдельную лёгкую компоновку. Цвета и тексты адаптированы под «Разряд», кириллица поддерживается шрифтами Inter, Lora и JetBrains Mono. В режиме reduced motion декоративное движение ограничивается.

Backend: Python 3.12, FastAPI, Pydantic, SQLAlchemy, psycopg, Argon2, pypdf, ReportLab. ML: NumPy, SciPy, scikit-learn. Точные версии зафиксированы в requirements.txt и package-lock.json. Для работы продукта не нужны GPU, внешняя LLM или платный API.

## 3. Основные правила

### Проверка навыков

Кандидат выбирает одну из двух специализаций и один из трёх уровней. Стаж не назначает грейд. До теста нужны имя, навыки и согласие на обработку. Один активный тест длится 30 минут. Повторный старт возвращает текущую попытку; ответы можно сохранить и восстановить после перезагрузки.

Восемь вопросов имеют одинаковый чертёж для заданной категории. Успех — не менее 70 баллов: при восьми равновесных вопросах это минимум шесть верных ответов, то есть 75 фактических баллов. Успех меняет категорию, неудача сохраняет предыдущую. Повтор того же уровня после неудачи доступен через сутки; нижний уровень можно попробовать сразу, если нет блокировки после успешного подтверждения. После успеха смена категории ограничена 90 днями. Повторная отправка завершённой попытки возвращает прежний результат.

### Обратный найм

Компания создаёт потребность, выбирает категорию и получает ранжированный банк. Потребность не обязана становиться вакансией. Нельзя переопределить категорию потребности несовместимым query-фильтром. Без потребности доступен обзор опубликованных подтверждённых специалистов; персональная релевантность надёжнее интерпретируется после выбора потребности.

Приглашение содержит роль, текст, контакт компании и положительный диапазон зарплаты. До отправки проверяется публикация профиля. Два одновременных запроса не создают два активных приглашения одной пары. Состояния: sent → viewed → accepted / declined; отправитель может перевести sent / viewed в withdrawn. Из терминального состояния новый переход запрещён. Повтор того же допустимого решения идемпотентен.

Принятие создаёт ContactGrant для конкретной компании. Контакт не появляется у других работодателей. Самостоятельный отклик также создаёт адресный доступ после отдельного согласия. Отзыв публикации убирает человека из нового поиска; ранее выданный доступ сохраняется. Возврат уже переданных контактных данных технически невозможен. В разделе профиля специалист видит выданные доступы и может отозвать ContactGrant для конкретной компании. Повтор принятия старого приглашения не восстанавливает отозванный доступ. Удаление аккаунта и управление сроками хранения остаются задачами пилота.

Вакансии поддерживают создание, редактирование и архив. Отклик на архивную вакансию запрещён. Статусы отклика: sent, reviewing, interview, rejected, withdrawn. Повторный отклик не создаётся. Задачи компании доступны кандидатам соответствующей специализации; проверка по явной рубрике обновляет сигнал активности при результате от 70, но не меняет грейд.

### PDF

Импорт принимает PDF до 5 МБ и до 20 страниц, проверяет сигнатуру и текстовый слой. Зашифрованный или повреждённый файл отклоняется. Исходный файл не сохраняется и не передаётся работодателю. Из текста извлекаются начальная строка, описание, email и совпадения с небольшим словарём навыков. Это эвристический черновик, возможны ошибки распознавания. OCR и произвольные макеты не поддерживаются. Экспорт собственного профиля формирует PDF с кириллицей.

## 4. API

Swagger: `/api/v1/docs`; JSON: `/api/v1/openapi.json`. Экспорт контракта лежит в `docs/openapi.json`. Схемы входных данных строгие: неизвестные поля отклоняются, поэтому нельзя подставить grade, score или чужой company_id через сохранение профиля. Ответы с условным раскрытием контактов дополнительно описаны ниже; OpenAPI не заменяет серверную проверку прав.

| Группа | Методы и пути | Доступ |
|---|---|---|
| Система | GET health, catalog, metrics | Публичный |
| Авторизация | POST auth/register, verify, login, logout, recover, resend, reset | По сценарию; ссылки одноразовые |
| Текущий пользователь | GET auth/me | Сессия |
| Демо | POST auth/demo/{role} | Только DEMO_MODE |
| Профиль | GET/PUT profile; GET profile/pdf; POST profile/import-pdf | Кандидат |
| Компания | GET/PUT company | Работодатель |
| Тесты | GET/POST assessments; PUT {id}/answers; POST {id}/submit | Кандидат-владелец |
| Подбор | GET/POST needs; GET candidates; GET candidates/{id} | Работодатель |
| Приглашения | GET/POST invitations; PATCH invitations/{id} | Участники диалога |
| Вакансии | GET/POST vacancies; PUT/PATCH vacancies/{id}; GET company/vacancies | Чтение публичное; изменение владельцем |
| Отклики | POST vacancies/{id}/applications; GET applications; PATCH applications/{id} | Кандидат и владелец вакансии |
| Практика | GET/POST challenges; POST challenges/{id}/submissions; POST submissions/{id}/review | Соответствующая роль и владелец |
| ФСП | POST/DELETE integrations/fsp | Кандидат; привязка только в демо |

Все пути в таблице имеют префикс `/api/v1`. Авторизация — cookie `razryad_session`. Поиск принимает need_id, specialization, grade, skill, fsp, offset и limit; limit не больше 100. Ответ: items, total, offset, limit. Списки собственных сущностей небольшого прототипа пока возвращаются целиком.

Candidate DTO содержит профиль, category, achievements, grade_change_available_at, contacts_unlocked. Поля email/contact отсутствуют до согласия; consent и fsp_id доступны только владельцу. Match содержит score, mode, baseline_score, learned_score, blend, matched_skills, missing_skills, factors, explanation и notice. contribution показывает вклад фактора в формулу; итог гибрида описывается отдельно.

Attempt DTO содержит вопросы без правильных ответов и внутреннего seed, сохранённый черновик, сроки, результат. После завершения outcomes указывает корректность по каждому вопросу. Invitation DTO содержит условия и статус, а candidate_email/candidate_contact — только для получившей доступ компании.

| Код | Значение |
|---|---|
| 400 | Недействительная ссылка или некорректный запрос |
| 401 | Нет действующей сессии |
| 403 | Не та роль, недопустимый Origin; неподтверждённая почта только при включённом EMAIL_VERIFICATION_REQUIRED |
| 404 | Ресурс отсутствует или скрыт правилами владения |
| 409 | Дубликат, закрытый переход, период ожидания |
| 413 | Превышен размер запроса или PDF |
| 422 | Ошибка полей, зарплаты, категории или формата |
| 429 | Ограничение частоты авторизации |
| 503 | Почта или официальная интеграция не настроена |

Ошибки имеют поле detail на русском; при валидации также fields с путём поля и машинным кодом. Клиент показывает ошибку, сохраняет заполнение и позволяет повторить действие. При 401 кабинет направляет пользователя на вход.

## 5. Защита и конкурентные операции

Пароли хешируются Argon2, токены — SHA-256 от криптографически случайной строки. Cookie HttpOnly, SameSite=Lax, Secure включается для HTTPS. Origin проверяется для мутаций; запросы без Origin допускаются для серверных клиентов. CORS с произвольным источником не включён. Ответы API получают no-store, nosniff, DENY и same-origin referrer policy.

Уникальные ограничения защищают email, внешний ID ФСП, пару доступа, отклики и решения задач. В PostgreSQL критические переходы тестов/приглашений используют блокировку строки. В SQLite мутации начинают BEGIN IMMEDIATE до чтения, поскольку SELECT FOR UPDATE там не действует. Конкурентные тесты проверяют повторное приглашение и старт попытки.

Публичный сериализатор исключает контактные поля и маскирует очевидные email, URL, телефоны и @псевдонимы в свободном тексте. Это не гарантирует обнаружение намеренно замаскированного контакта. PDF-резюме не публикуется. В Audit не записываются пароли, токены и тексты резюме.

Ограничитель авторизации хранится в памяти одного процесса: 30 запросов в минуту на IP и путь. Он не заменяет распределённый лимитер; за reverse proxy клиенты могут делить IP. До внешнего пилота нужен согласованный trusted proxy и Redis/edge-limiter. Лимит Content-Length не является потоковой защитой от всех chunked-запросов: на внешнем прокси обязателен реальный лимит тела. Разбор PDF должен быть вынесен в ограниченный по времени и памяти worker перед приёмом недоверенного массового трафика.

## 6. ФСП, Keycloak и ATS: проект интеграции

Сейчас доступен только маркированный демореестр. ID DEMO-FSP-2026 уникален; повторная привязка к другому профилю отклоняется. Достижения содержат source=demo_registry. Отключение удаляет локальные демонстрационные достижения. Никакие данные не отправляются в ФСП.

Промышленный контракт: OIDC Authorization Code + PKCE через Keycloak; обязательные state и nonce; проверка issuer, audience, подписи по JWKS и срока. Идентичность связывается по паре issuer/sub, а не по изменяемому email. Account linking требует действующей локальной сессии и повторного подтверждения, чтобы не захватить чужой профиль.

После согласия отдельный адаптер получает результаты соревнований из согласованного API. Ключ импорта — provider + external_event_id + participant_sub. Хранятся source, fetched_at, version и статус отзыва; обновление идемпотентно. Устаревшая запись не становится «актуально подтверждённой» при сетевой ошибке. Webhook проверяется подписью и защитой от повторов. Секреты остаются на сервере. До получения спецификации API, credentials и правовой модели такой адаптер нельзя считать подключённым.

ATS: предложен outbox событий vacancy.published, application.created, invitation.accepted и application.status_changed. Доставка с event_id, tenant_id, версией схемы и idempotency key; exponential backoff с jitter, dead-letter очередь, ручное повторение. Подпись HMAC, отдельные ключи компании, контроль статусов и конфликтов. Передача контактов проверяет ContactGrant при формировании каждого события. Это документированный контракт развития; отправки в реальную ATS в версии 1.0 нет.

## 7. Запуск, обновление и восстановление

Полные команды для Windows и Docker приведены в README. Локальный старт использует SQLite, Docker — PostgreSQL. В Compose доступ наружу ограничен 127.0.0.1; порт БД не публикуется. Mailpit показывает тестовую доставку писем. API и web выполняются непривилегированными пользователями контейнеров.

| Переменная | Назначение |
|---|---|
| DATABASE_URL | SQLAlchemy URL SQLite или PostgreSQL |
| DEMO_MODE | Демоаккаунты, возврат ссылки письма, демореестр ФСП |
| PUBLIC_ORIGIN | Разрешённый origin и адрес ссылок в письмах |
| COOKIE_SECURE | Secure cookie при HTTPS |
| SMTP_HOST / PORT / FROM | Сервер и отправитель почты |
| SMTP_STARTTLS / USERNAME / PASSWORD | Защищённое SMTP-соединение и учётные данные |
| MODEL_PATH | Путь к проверяемому JSON модели |
| MAIL_DIR | Локальные письма только для демо без SMTP |
| API_INTERNAL_URL | Адрес API для rewrites во время сборки Next.js |

В локальном Python значения берутся из окружения: .env автоматически не читается. Compose читает .env для подстановок. Текущая Compose-конфигурация намеренно подключает API к Mailpit; для внешнего SMTP нужно изменить environment сервиса api. Смена API_INTERNAL_URL требует пересборки web.

Начальная схема создаётся create_all на пустой БД. Это не система миграций существующих таблиц. До первого изменения схемы на пилоте требуется ввести Alembic, зафиксировать baseline текущей модели, проверить upgrade/rollback на копии и сделать резервную копию. Не использовать удаление volume как способ обновления рабочих данных.

Резервная копия PostgreSQL: выполнить pg_dump -U razryad -d razryad -Fc -f /tmp/razryad.dump внутри db-контейнера, затем docker compose cp db:/tmp/razryad.dump в закрытое хранилище. Восстановление проверять в отдельной БД командой pg_restore, после чего выполнить вход, чтение профиля и историю приглашений. В Windows нельзя пропускать бинарный dump через старый текстовый PowerShell redirect. SQLite копировать штатным backup API при остановленных мутациях. Копии содержат персональные данные и требуют ограничения доступа.

Перед внешним пилотом: HTTPS, DEMO_MODE=false, COOKIE_SECURE=true, отдельные секреты, реальный SMTP, политика хранения/удаления и отзыва согласий, проверка компаний, централизованный аудит и мониторинг, резервное копирование с испытанием восстановления, миграции. Это эксплуатационные условия, а не выполненная сертификация.

## 8. Диагностика

- Порт 3000 занят: уже работает dev-сервер или web-контейнер. Выберите один способ запуска.
- 503 при включённой почтовой верификации: настроить SMTP. На текущем стенде EMAIL_VERIFICATION_REQUIRED=false и почта для регистрации не нужна.
- Пустой демобанк: выполнить backend.seed в той же БД, которую использует API.
- Ошибка Origin: PUBLIC_ORIGIN должен точно совпадать со схемой, хостом и портом браузера.
- Модель не найдена: подбор остаётся доступным с mode=rules-v1; выполнить обучение или вернуть model.json.
- При включении почтового режима Docker отправляет письма только в локальный Mailpit на localhost:8025. На текущем стенде отправка писем для входа не нужна.
- Нужны результаты проверки: команды и критерии перечислены в следующем документе; приватные локальные логи в Git не входят.
