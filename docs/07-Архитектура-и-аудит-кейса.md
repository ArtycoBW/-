# Архитектура и сверка с исходным кейсом

Версия 1.3, 11 октября 2026. Основание: исходное техническое задание ФСП «Цифровая платформа-агрегатор ИТ-вакансий…», разделы 2.1–3.5. Собственное расширенное ТЗ проекта не подменяет требования организатора.

## Результат аудита

Основная механика кейса реализована сквозным сценарием: кандидат заполняет профиль, выбирает уровень, сдаёт индивидуальный вариант теста, получает категорию; компания создаёт потребность, находит кандидата и предлагает зарплату; контакт раскрывается после адресного согласия. Дополнительные сценарии вакансий, откликов, практики и PDF работают.

Подтверждение email из пункта 2.2.4 работает на https://razryad.agropulseai.ru. Регистрация доставляет одноразовую ссылку через SMTP Timeweb; до подтверждения вход закрыт. Проверены получение письма, одноразовость, Secure/HttpOnly-cookie, вход, восстановление пароля и отзыв старых сессий. Адрес прототипа из заявки сохранён.

Нельзя считать научно подтверждёнными профессиональные грейды или эффективность реального найма. Организатор допускает собственную синтетику; её происхождение и ограничения явно описаны. Официальный API ФСП не предоставлен самим организатором, поэтому демонстрационный реестр соответствует допустимому формату хакатона, но не является подключением к реальному реестру.

Это модульный монолит с отдельным веб-приложением. Отдельные микросервисы и распределённая очередь не нужны для проверки основной механики и не заявляются как реализованные. Модель работает локально на CPU, внешняя LLM не получает резюме. Доменные данные не хранятся в браузере; localStorage содержит состояние меню, избранное и черновик практики, привязанные к ID пользователя. Сессионный токен доступен только через HttpOnly-cookie.

### Ключевые инварианты

- Специализация и подтверждённый грейд задают одну категорию. Сохранение профиля не может произвольно поменять подтверждённую специализацию.
- Профиль попадает в банк только с согласием, публикацией и подтверждённым грейдом. Достижения ФСП не заменяют тест.
- ContactGrant уникален для пары компания–кандидат. Приглашение без принятия не выдаёт контакт; отзыв доступа применяется при следующем чтении API.
- Публикация вакансии и приглашение требуют диапазон зарплаты. Отклик и решение практики защищены от дублей уникальными ограничениями БД.
- Состояние попытки, ответы и срок хранятся на сервере. Перезагрузка браузера не обнуляет таймер. Неудача сохраняет уже подтверждённый грейд.
- Начальные данные не обновляют пользовательские правки. Повтор seed не воссоздаёт отозванные согласия.

| Потребность компании | Категория, навыки, задачи, формат, зарплата | Сохранение и переключение потребностей в подборе |

| Статусы и приватность | Приглашения и отклики видны только участникам | API-тесты двух работодателей, отказа и отзыва |

| Вакансии и самостоятельные отклики | Публикация, редактирование, архив, поиск, избранное, письмо и согласие | Дополнительный сценарий реализован |
| Регулярная практика | Задачи компании по специализации, рубрика, ответ, оценка, обновление свежести при ≥70 | Каталог доступен постоянно; календарной рассылки нет |

| API и документация | OpenAPI с запросами/ответами/ошибками; PDF, PPTX, инструкция | Автотест непустых схем ответов; исходники открыты |
| Воспроизводимость | Lock-файлы, Docker, seed, backup/restore, команды проверок | Проверено на Windows/Docker/Chrome; Safari не проверен |

## Выпуск 1.3 и промышленный пилот

Выпущены постоянный домен, SMTP, обязательное подтверждение почты, восстановление пароля, миграции, управление аккаунтом, общий лимит запросов, локальный мониторинг и ежедневное резервирование с проверкой восстановления. Локальный OIDC и внешний текстовый ML-пилот описаны в документе 12.

Для промышленного пилота требуются:

1. Предоставленный Федерацией контракт и доступ к официальному реестру.
2. Экспертная калибровка заданий и уровней по каждому направлению.
3. Оценки работодателей и проверка качества продуктового подбора на реальных сценариях найма.
4. Независимый хостинг, внешние копии и оповещения с согласованными RPO/RTO и SLA.
5. Масштабирование поиска по результатам нагрузки, проверка компаний и процедуры модерации.

Эти условия относятся к промышленной эксплуатации и внешней валидации. Проверенные функции хакатонного стенда перечислены в документе 09.
